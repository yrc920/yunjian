# 16 · 已知限制

这里记录**当前版本**明确不做的能力与边界。每条都给出影响与可行方向，便于评估是否需要在你的场景中补齐。

## 16.1 安全

| # | 限制 | 影响 | 方向 |
| --- | --- | --- | --- |
| S1 | 密码在应用层做可逆 XOR，不是加密 | 未启用 HTTPS 时密码可被还原 | 部署强制 TLS；后续改为服务端挑战-响应 |
| S2 | 服务间 gRPC 明文 | 只适合回环或容器内网 | 拆多机时加 mTLS 或服务网格 |
| S3 | 自动登录令牌存偏好设置，未进系统钥匙串 | 同用户进程可读；离线依赖全盘加密 | 接 macOS Keychain / Windows DPAPI |
| S4 | 资源下载鉴权是"同会话"粒度 | 同会话成员知道资源名即可下载对方其它文件 | 按 `chat_message` 关联授权，并联合归档表 |
| S5 | 下载鉴权结果缓存 60 秒 | 被移出群后短期内仍可能命中缓存 | 成员变更时主动失效，或缩短 TTL |
| S6 | 改密只吊销令牌，不主动断开已建立的连接 | 攻击者已在线时可持续到下次断线 | 改密后调用 `KickSession` 强制下线 |
| S7 | 没有二次验证、登录审计与异地提醒 | 账号被盗后只能靠改密止损 | 增加登录日志与可选 TOTP |
| S8 | 消息写入限流只覆盖文本/图片/文件 | 其它帧可高频调用 | 对全部请求加连接级令牌桶 |

## 16.2 可靠性

| # | 限制 | 影响 | 方向 |
| --- | --- | --- | --- |
| R1 | StatusServer 单实例 | 控制面故障期间无法登录、续租 | 主备或按 uid 分片多活 |
| R2 | ResourceServer 单实例、本地磁盘 | 资源层无法水平扩展，磁盘故障即丢失 | 对象存储 + 多实例 |
| R3 | 跨实例投递是尽力而为 | 对端实例不可达时只能等下次登录同步 | 失败重试队列 / 离线推送 |
| R4 | 离线消息没有主动推送 | 用户上线前看不到新消息提醒 | 接入 APNs / FCM 或自建推送 |
| R5 | 客户端重连不跨实例故障转移 | 原实例长时间不可用时只能回登录页 | 重连前重新走 `GetChatServer` |
| R6 | 归档只搬到同库的归档表 | 数据量很大时仍占用同一实例 | 归档到冷存储或对象存储 |
| R7 | 没有数据库迁移框架 | 结构变更靠导入快照或手工 DDL | 引入版本化迁移脚本 |

## 16.3 性能与容量

| # | 限制 | 影响 | 方向 |
| --- | --- | --- | --- |
| P1 | 登录首屏最多 50 个会话 | 会话很多时要多次翻页 | 提高首屏数量或按活跃度预取 |
| P2 | 会话列表每行带相关子查询 | 会话特别多时查询变慢 | 预聚合未读数或加缓存 |
| P3 | 逻辑线程固定 4 个分片 | 单分片热点会话仍串行 | 按 uid 扩容分片 |
| P4 | 资源分片 64 KB，单连接串行 | 大文件在弱网下耗时明显 | 多连接并行或更大分片 |
| P5 | 单帧 8 KB | 长文本被拆成多条消息 | 提高上限或改为分片协议 |
| P6 | 单容器把 MySQL/Redis 与应用放在一起 | 无法独立扩缩容，故障域重合 | 拆分托管数据库与多容器 |

## 16.4 功能

| # | 限制 | 说明 |
| --- | --- | --- |
| F1 | 单端登录 | 同一账号只能一端在线，后登录顶掉前一个 |
| F2 | 群人数上限 200，一次建群最多邀请 50 人 | 见 `const.h` |
| F3 | 不支持转让群主、@所有人、逐条已读 | 群资料页只展示成员角色 |
| F4 | 没有黑名单、消息举报、敏感词过滤 | 删除好友是单向的，对方无感知 |
| F5 | 没有消息编辑、表情回应、语音/视频通话 | 消息能力集中在文本与文件 |
| F6 | 撤回不删除已下载到本机的文件 | 界面不再展示，缓存目录仍保留 |
| F7 | 资源上传的断点只在运行期有效 | 客户端退出后从第 1 片重传；服务端进度保留 1 小时 |
| F8 | 视频首帧依赖 QtMultimedia 后端 | 缺少解码器时退化为通用图标 |
| F9 | 本地库无全文索引 | 搜索只覆盖已缓存的文本消息 |
| F10 | 同名文件冲突按内容 MD5 与序号处理 | 多设备同时上传同名不同内容仍可能重名 |
| F11 | 界面文案只有中文 | 未做国际化 |
| F12 | 合并转发最多 20 条、整包 6 KB | 超出部分从末尾截断 |

## 16.5 运维

| # | 限制 | 影响 | 方向 |
| --- | --- | --- | --- |
| O1 | 只有 `/healthz`，没有 Prometheus 指标 | 只能看日志与队列深度 | 暴露 `/metrics` |
| O2 | 日志为本地轮转文件 | 多实例排查要逐台登录 | 接入集中日志（Loki/ELK） |
| O3 | Docker 镜像首次构建约 1 小时 | 发布链路较慢 | 预构建镜像仓库 / 分层缓存 |
| O4 | 没有自动证书续期 | 90 天证书需人工替换 | 接入 certbot 或云厂商自动续期 |
| O5 | 数据库备份需手工执行 | 依赖运维纪律 | 定时任务 + 恢复演练 |

## 16.6 适用边界

这套系统适合：

- 团队内部的即时通讯与文件传输；
- 学习分布式 IM 的连接管理、租约、消息路由与资源分片；
- 单区域、几千在线用户规模的部署。

以下场景需要先补齐上面的限制：

- 公网大规模社交产品（需要多活、审核、推送、对象存储）；
- 强合规场景（需要审计、端到端加密、密钥托管）；
- 需要多端同时在线的产品（当前是单端登录）。
